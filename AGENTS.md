# Правила проекта GeoEco Monitor

## Кодировка
- Все файлы читать и сохранять только в UTF-8.
- Не использовать массовые перезаписи с неявной кодировкой.
- При признаках mojibake остановить правку, восстановить файл из git и повторить минимальным diff.

## Безопасное редактирование
- Перед правками проверять `git status`.
- Для точечных изменений использовать `apply_patch` или редактор с гарантированным UTF-8.
- После правок запускать `git diff --check` и проверять diff на неожиданные изменения.

## Методические ограничения
- Интерфейс и документация используют формулировки: “аналитический дашборд”, “панель мониторинга”, “карта анализа”, “публичный интерфейс”.
- Не использовать термин “админка”.
- Не утверждать, что приложение измеряет или доказывает загрязнение.
- Разрешенные итоговые классы: `благоприятное`, `удовлетворительное`, `напряженное`, `проблемное`.
- Всегда показывать ограничение: результат является предварительной дистанционной оценкой и не заменяет лабораторные измерения, экспертизу и натурное обследование.

## Проверки
- `npm run lint`
- `npm run build`
- `pytest`
- `ruff check`

## Документация этапов
- После каждого реализованного этапа или крупной задачи добавлять краткий отчет в папку `docs/`.
- В отчете фиксировать: цель, что реализовано, ключевые файлы, выполненные команды, результаты проверок, ограничения и следующий шаг.
- Документация должна быть на русском языке и в UTF-8.
